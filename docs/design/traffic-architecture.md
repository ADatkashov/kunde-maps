# Road traffic: status and extension point

**Status (2026-11-22): KUNDE Maps shows no traffic.** The reference mock-up colours roads green/yellow/red; we have no verified live traffic
source, so nothing of the kind is drawn and nothing is called "live traffic". Route ETAs are free-flow estimates and say so ("without traffic").
Paid traffic APIs and scraping of other map products are out of scope (`AGENTS.md` 4-5) without explicit permission.

## What was checked
- Valhalla (our router) supports historical speed profiles and live traffic tiles, but we have neither dataset.
- OSM carries no live traffic. Public open datasets of *measured* speeds for Kazakhstan: none found that are current and licensable.
- The lawful path is privacy-preserving aggregation of consenting users' GPS (roadmap EP-MAP-006 / MAP-016), which needs the Phase 6 native clients first.

## Extension point (not wired to the UI today)
Keep the base style free of traffic. When a source exists:
1. **Data**: a separate vector/PMTiles source `traffic` (road segment id -> speed ratio, timestamp, `source`, `license`, `confidence`), versioned and
   expiring (stale data is hidden, never shown as current).
2. **Style**: one `line` layer injected by `withPlaces()` in `apps/web/map.js` (same mechanism as `route`/`places`/`buildings-3d`) *above* road casings,
   with 3 colour classes from `speed_ratio`; the style files generated by `scripts/build-style.py` stay unchanged.
3. **UI**: the Layers popover already lists "Traffic" with the reason it is unavailable; replace that static row with a switch only when the source is live,
   with a legend and the data timestamp. Routing may then pass a traffic profile to Valhalla and label ETAs accordingly.
4. **Quality gate**: a test that fails if a traffic layer exists while no `config.trafficUrl` is set (`scripts/test-shell-ui.js` already asserts that
   no traffic layer is ever added today).
